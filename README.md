# 판독: 영양제 광고 판독기

쇼핑몰·SNS의 영양제·건강식품 광고 문구를 붙여넣거나 캡처해서 올리면, 문구마다 **식약처가 인정한 기능성 범위를 넘는지**, **논문은 뭐라고 하는지**, **최근 회수·이상사례가 있었는지**, **전문가 추천을 내세운 광고인지**를 출처와 함께 몇 초 안에 알려줍니다.

- 트랙: 라이너 해커톤 트랙 1 · **3. 라이너 API 활용 저비용 헬스케어 앱**
- 판독 한 건: **약 6~8초, 라이너 API 비용 약 2~4원** (실측, 아래 참고)

### 지금이 시점이다
- 식약처가 AI로 만든 가상 전문가 추천 광고를 제재하는 시행규칙 개정을 입법예고했고, **11월 27일 시행 예정**으로 보도됐습니다 ([데일리팜](https://www.dailypharm.com/user/news/341236)). 입법예고 단계 기사라 최종 시행은 식약처 공고로 확인이 필요합니다.
- 식약처는 AI 감시 시스템 "AI캅스"로 온라인 광고를 단속합니다 ([푸드투데이](https://www.foodtoday.or.kr/news/article.html?no=199300)). **단속하는 쪽**의 도구이고, 소비자가 쓰는 도구는 아닙니다.

### 경쟁·대체재
| 무리 | 서비스 | 하는 일 | 판독과의 차이 |
|---|---|---|---|
| 국내 영양제 앱 | 필라이즈 | 내 건강 데이터와 영양제 함량을 비교해 부족·과다 성분 안내 (분석 이용 33만 회) | 광고 문구가 과장인지는 판정하지 않음 |
| | 팜픽 | 성분·함량·부원료 해설 | 광고 검증 없음 |
| 해외 근거 등급 앱 | Evidence Stack, GutCited, Eclo, Suppi, Prove It | 성분별 근거 등급 (A~D 등) | 사람이 정리한 **고정 DB**, 영어, **한국 규제(식약처 인정 범위)를 모름** |
| 논문 검색 AI | Consensus | 연구가 주장을 지지하는지 보여줌 | 범용 검색. 광고·규제 대조 없음 |
| 정부 | 식약처 AI캅스 | 불법 광고 자동 탐지·차단 | 단속용. 소비자용 아님 |
| 정부 | 식품안전나라 제품 검색 | 제품명으로 신고 정보 조회 | 광고 문구와 대조해 주지 않음 |

광고 문구를 식약처 인정 기능성·논문·최근 안전 소식과 **한 화면에서 대조해 주는 소비자용 서비스는 찾지 못했습니다.** (공개 자료 기준. 필라이즈 앱 내부 기능은 직접 확인하지 못함)

### 결론: 진행
- 문제 크기가 숫자로 확인되고, 규제 변화로 관심이 높은 시점입니다.
- 비어 있는 자리가 분명합니다: **소비자 쪽**에서 **광고 문구 단위**로 **한국 규제 기준**을 대조하는 도구.
- 같은 엔진으로 판매자용 "광고 사전 검수"로도 확장할 수 있습니다 (수익 모델 후보).

## 2. 왜 라이너여야 하나

| 판독의 핵심 | 라이너 API | 라이너가 아니면 |
|---|---|---|
| 식약처 인정 기능성·최근 회수 소식을 **실시간으로** | Web Search (`date_range: past_year`), $1 / 1,000회 | 고정 DB는 매일 바뀌는 광고·회수 소식을 못 따라감. 다른 검색 API는 $5~8 / 1,000회 |
| 논문 근거와 **인용 수·저널** | Scholar Search, **$0.3 / 1,000회** | 논문 메타데이터를 주는 검색은 드물고 비쌈 |
| 과장 여부·근거 등급을 **확률로** 판정 | Decisions (`noul`·`choice`·`score`), **출력 토큰 무료**, 판정 정밀도 100% (아래 5장) | LLM에 JSON을 요청하고 파싱해야 하고, 확률이 없어 "판단 보류"를 정직하게 못 보여줌 |
| 광고 이미지에서 문구 추출 | Router (이미지 입력, `routing_strategy: cost`) | 회사별 키·SDK 따로 |

**저비용 실측** (예시 광고 4건, `usage.cost` 기준): 건당 **$0.0016~0.0028 (약 2~4원)**, 6~8초.
Decisions 한 번이 약 $0.00002, Scholar 검색 한 번이 $0.0003입니다. 사람이 광고를 하나씩 확인하는 비용과 비교가 되지 않습니다.

## 3. 설계

### 흐름
```
광고 텍스트 / 이미지
  └ 1. 추출 (Router, json_schema): 제품명 · 핵심 원료 최대 3개 · 효과 주장 문구 최대 6개
  └ 2. 병렬
       ├ 제품 신고 확인   식품안전나라 Open API C003 (품목제조신고: 주된기능성·섭취 주의)
       ├ 인정 기능성 검색  라이너 Web Search → 식약처 자료 우선
       ├ 최근 안전 소식   라이너 Web Search, 최근 1년, SNS·블로그 제외
       ├ 논문 검색        라이너 Scholar Search (RCT·메타분석 우선 검색어)
       └ 전문가 추천 여부  라이너 Decisions noul
  └ 3. 판정
       ├ 문구마다  Decisions: 인정 범위 초과 확률(noul) + 성격(choice: 질병·의약품 오인·과장·미인정·문제없음)
       └ 원료마다  Decisions score: 논문 근거 강도 → A~D 등급
  └ 결과는 단계마다 SSE로 바로 화면에 표시
```

### 판정 규칙 ([src/verdict.ts](src/verdict.ts))
- **위험**: 질병 치료·예방이나 의약품 오인 표현일 확률이 높음 (건기식 광고에서 금지된 유형)
- **주의**: 인정 범위를 넘을 확률 65% 이상
- **판단 보류**: 확률이 35~65%이거나 두 판정이 서로 어긋날 때. 단정하지 않는 것이 원칙
- **인정 범위**: 넘지 않을 확률이 높고 문제없음 판정과 일치

### 안전·책임 원칙
- 진단·처방·법적 판단이 아닌 **공개 자료 기반 참고 정보**라고 화면에 명시
- 모든 판단에 출처 링크. 공식 자료와 비공식 출처를 태그로 구분
- 사용자 건강 정보는 받지 않음 (광고 문구만 입력)
- 입력 검증: 텍스트 5,000자, 이미지 PNG·JPG·WEBP 8MB 이하


### 앱처럼 쓰기 (PWA)
- **설치:** 안드로이드·PC 크롬에서는 화면 위 "앱으로 설치" 버튼, 아이폰 Safari에서는 공유 → 홈 화면에 추가.
- **공유하기로 바로 판독:** 설치하면 쇼핑앱·SNS에서 광고 문구를 "공유"할 때 판독이 목록에 나오고, 고르면 바로 판독을 시작합니다 (안드로이드, manifest `share_target`).
- **캡처 붙여넣기:** 글 상자에 캡처 이미지를 그대로 붙여넣으면 이미지로 판독합니다.
- **오프라인:** 첫 화면은 서비스 워커가 캐시해 바로 열립니다. 판독 요청은 항상 서버로 보내고 캐시하지 않습니다.
- 설치는 HTTPS 주소(또는 localhost)에서만 됩니다. 배포할 때 HTTPS를 붙여야 합니다.

## 4. 실행

Node 22.18 이상 (TypeScript를 그대로 실행). 설치할 패키지가 없습니다.

```bash
cp .env.example .env    # LINER_API_KEY 입력
npm start               # http://localhost:8000
npm test
```

- `FOODSAFETY_API_KEY`가 없으면 식품안전나라 **공개 샘플 키**로 조회합니다. 샘플은 일부 데이터만 돌려줘서 제품 신고 여부가 "확인 불가"로 나올 수 있습니다. [식품안전나라 Open API](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?svc_no=C003)에서 무료 인증키를 신청해 넣으면 전체 46,000여 개 품목을 조회합니다.
- 판정 모델은 `DECISION_MODEL`로 바꿀 수 있습니다 (기본 `perplexity/pplx-decider-v1.2`, 아래 정확도 측정으로 고름).
- `npm run eval`: 정답이 있는 광고 문구 52개로 판정 정확도를 다시 잽니다. 모델을 여러 개 비교하려면 `node --env-file=.env eval/run.ts 모델1 모델2`.

### 서버 배포 (Docker Compose)
서버 한 대에 Docker만 있으면 됩니다.

```bash
cp .env.example .env          # LINER_API_KEY 입력 (없으면 시작하지 않고 알려 줌)
docker compose up -d --build  # http://서버주소:8000
docker compose logs -f app    # 로그 보기
```

- 업데이트: 코드를 받은 뒤 `docker compose up -d --build`.
- 바깥 포트는 `.env`의 `HOST_PORT`로 바꿉니다 (기본 8000). 이 포트는 `docker-compose.override.yml`이 엽니다.
- **Coolify:** Build Pack을 Docker Compose로, 환경변수에 `LINER_API_KEY` 등을 넣고, `app` 서비스의 Domains에 `https://도메인:8000`(뒤의 `:8000`은 컨테이너 포트, 외부는 443). Coolify는 `docker-compose.yml`만 읽어서 호스트 포트를 열지 않으므로 서버의 다른 앱과 포트가 겹치지 않습니다.
- 컨테이너는 30초마다 `/health`로 상태를 확인하고, 꺼지면 다시 켜집니다.
- **공개 배포 보호:** IP당 10분에 10회, 서버 전체 동시 판독 6건까지 ([src/server.ts](src/server.ts), [src/limit.ts](src/limit.ts)). 서버 메모리에만 기록하므로 재시작하면 초기화됩니다.
- **라이너 한도 대응:** Scholar 검색은 계정 전체 초당 2회 한도라 서버 안에서 0.55초 간격으로 한 줄로 호출하고, 429·일시 장애는 Retry-After를 지켜 최대 3번 다시 시도합니다. 조회 하나가 실패해도 판독은 멈추지 않고 그 칸만 비워 둡니다.
- **휴대폰 설치(PWA)는 HTTPS 주소에서만 됩니다.** 앞단에 HTTPS를 붙이세요: Caddy·Nginx 리버스 프록시, Cloudflare Tunnel, 또는 Coolify·Railway 같은 플랫폼의 도메인 기능.

## 5. 판정 정확도

### 무엇으로 쟀나
[eval/cases.json](eval/cases.json)의 광고 문구 **52개**:
- **위반 31개:** 식약처 점검 결과 보도에 인용된 실제 적발 문구 ("먹는 위고비", "감기예방", "두드러기·건선·아토피 등 관리", "간장약", "골다공증 예방" 등). 출처 링크를 문구마다 달았습니다.
- **정상 21개:** 식약처 고시 기능성 문구 원문 ("관절 및 연골 건강에 도움을 줄 수 있음" 등), 건기식협회가 사용 가능하다고 밝힌 표현 ("공부체력이 필요할 때", "에너지 부스터" 등), 효능 주장이 아닌 섭취 안내 1개.

판정 단계(`judgeClaim`)만 잽니다. 인정 기능성 문구는 정답을 넣어 주므로, 검색이 엉뚱한 자료를 가져오는 경우는 이 수치에 들어가지 않습니다.

### 결과 (3회 측정 중 마지막 2회. 채택 모델 1회차는 위반 탐지 26/31로 1건 차이)
| 결정 모델 | 위반 탐지율 | 정상 통과율 | 정밀도 | 보류 제외 정확도 | 보류율 | 52개 비용 |
|---|---|---|---|---|---|---|
| **perplexity/pplx-decider-v1.2 (채택)** | **87.1%** (27/31) | **95.2%** (20/21) | **100%** (오탐 0) | **95.9%** | 5.8% | $0.0003 |
| typesafe/jev-1.14 | 87.1% (27/31) | 85.7% (18/21) | 93.1% (오탐 2) | 91.8% | 5.8% | $0.0015 |
| upstage/solar-decide | 100% (31/31) | 4.8% (1/21) | 60.8% | 61.5% | 0% | $0.0024 |

- **채택 모델은 정상 문구를 위반으로 잘못 찍은 적이 한 번도 없습니다** (정밀도 100%). 소비자에게 "위험"을 보여주는 서비스라 오탐이 가장 치명적이어서 이 모델을 골랐습니다.
- solar-decide는 모든 문구를 위반으로 찍어 쓸 수 없습니다. 모델 선택이 결과를 크게 바꾼다는 점도 확인했습니다.

## 6. 확장 가능성

### 제품 사실 확인을 더 정확하게
지금은 제품명으로 식품안전나라 품목제조신고(C003)를 찾고, 원료 기능성은 라이너 Web Search로 찾습니다. 다음 순서로 정확도를 올립니다.

| 순서 | 확장 | 효과 |
|---|---|---|
| 1 | **식품안전나라 실제 인증키** | 샘플 데이터가 아닌 전체 46,000여 개 품목 조회. "신고 내역 없음 = 일반식품일 수 있음"을 근거 있게 말할 수 있음 |
| 2 | **기능성 원료 인정 현황 API(I-0040) 직접 사용** | 원료별 인정 기능성을 검색 대신 공식 데이터로. 엉뚱한 페이지를 기준으로 삼는 일이 없어짐 |
| 3 | **포장 사진에서 품목제조번호 읽기** | 이름 대신 신고번호로 정확히 조회. 같은 이름의 다른 제품과 헷갈리지 않음 |
| 4 | **수입 건강기능식품 데이터 연결** | C003은 국내 품목제조신고라 수입 제품이 빠질 수 있음 (확인 필요) |

### 서비스 확장
- **판매자용 광고 사전 검수 (수익 모델):** 같은 엔진으로 상세페이지를 올리면 위험 문구를 표시. 소비자용은 무료, 판매자·대행사용은 유료.
- **Vapi 음성 상담:** mawd 통화 파이프라인으로 "이 영양제 광고 믿어도 돼?" 전화 상담. 스마트폰이 익숙하지 않은 어르신용.
- **다른 분야:** 화장품("의약품처럼" 표현), 의료기기 광고. 규제 기준과 대조하는 구조는 같음.

## 7. 남은 일과 위험

- **식품안전나라 실제 인증키 발급** (회원가입 필요, 팀이 직접). 발급 전에는 데모 예시(한미루테인골드)처럼 샘플 데이터에 있는 제품만 신고 확인이 됩니다.
- **암시 표현 보강**: 정확도 측정에서 놓친 유형(간접 암시). 판정 질문에 "직접 말하지 않아도 효능을 암시하는가"를 추가하고 다시 재기.
- **검색 단계까지 포함한 평가**: 지금 수치는 판정 단계만 잰 것. 실제 광고 전문으로 처음부터 끝까지 재야 함.
- **추출 결과가 매번 조금씩 다름**: 같은 광고도 문구 추출이 달라질 수 있음 (Router 특성).
- 공개 배포 시 호출 제한(요청 수 제한)과 비용 상한이 필요합니다. 지금은 없습니다.
